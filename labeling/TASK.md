# ТЗ: LLM-переразметка пар товаров

Для Дани (закинь этот файл своему Клоду вместе с описанием своей инфры — он напишет код).

## Задача

Разметить пары товаров открытой LLM: один и тот же это товар или нет.
Метки пойдут в обучение наших моделей вместо шумных меток организаторов.

## Данные (лежат рядом в этой папке / появятся после нарезки)

- `pilot_pairs.parquet` (~25k пар) — ПИЛОТ, размечать его ПЕРВЫМ.
  Колонки: id1, id2, name1, attributes1, name2, attributes2, category,
  target_human (человеческое золото 0/1 — для самопроверки, в промпт НЕ подавать!).
- `battle_pairs.parquet` (~300k пар, появится позже) — боевой набор спорных пар,
  те же колонки, но без target_human. Отсортирован по приоритету — размечать сверху вниз,
  сколько успеется.

## Промпт (формулировка важна, не менять смысл)

Системный: "Ты эксперт маркетплейса по товарным дублям."

Пользовательский (на каждую пару):
```
Товар A: {name1}
Атрибуты A: {attributes1}

Товар B: {name2}
Атрибуты B: {attributes2}

Это один и тот же товар в одном и том же варианте исполнения?
Разные размер, цвет, объём, вес, комплектация, количество в упаковке —
это РАЗНЫЕ товары. Разное написание/язык/порядок слов при совпадении
товара — тот же товар. Ответь одним словом: Да или Нет.
```

Атрибуты можно обрезать до ~400 символов каждый (как есть, JSON-строкой).

## Выход

Скор — вероятность "Да":
- лучший вариант: logprob токенов "Да"/"Нет" при temperature=0 (1 запрос на пару);
- если logprobs недоступны: 5 сэмплов при temperature=0.7, скор = доля "Да".

Файл(ы): parquet с колонками id1, id2, llm_score (float 0..1).
Чанками по ~50k пар (чтобы обрыв не терял работу).
Рядом положить meta.json: {"model": "<точное имя и квантование>", "endpoint_type": "...",
"method": "logprob|vote5", "seed": ..., "date": "..."} — нужно для воспроизводимости
(правила соревнования: код разметки проверяется, только открытые лицензии).

## Порядок

1. ВАЖНО: модель — только с открытой лицензией (Qwen/Mistral/Gemma и т.п.
   локально; никаких проприетарных API — за это дисквал).
2. Пилот: разметить pilot_pairs, посчитать сверку с target_human:
   accuracy и average_precision_score(target_human, llm_score).
   Ориентир: у разметки организаторов на схожих парах accuracy ~0.85-0.9.
   Если у твоей модели сильно хуже — пишем в чат, думаем (другая модель/промпт).
3. Если пилот ок — battle_pairs сверху вниз, чанки скидывать по мере готовности.
