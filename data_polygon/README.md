# Полигон: быстрые сравнения моделей и препроцессинга

`llm_sample_2m.parquet` — 2.17M LLM-пар (id1, id2, target) для дешёвых экспериментов.
Эпоха tiny на T4 ~50 мин, e5-small ~2 ч, e5-base на A100 ~40 мин.

## Как нарезан

Из train-части LLM-пар (вне общего holdout seed 13/3%) взято случайное
подмножество КОМПОНЕНТ (union-find по товарам, seed 99) — товары полигона
не пересекаются с holdout, метрики сравнимы с таблицей в solution/README.md.

## Протокол сравнения (иначе выводы не переносятся)

1. Валидация — общий llm-holdout (seed 13, уверенные пары, macro PR-AUC).
   Он строится из ПОЛНОГО matches_llm.parquet, как во всех наших ноутбуках.
2. Кандидаты сравниваются при одинаковом бюджете: 1 эпоха по полигону,
   одинаковый effective batch (~256) и протокол LR (warmup 3%, linear).
3. Что сравнивать МОЖНО: препроцессинг/формат текста, max_len, LR, приёмы
   обучения; модели ОДНОГО класса размера (base vs base).
   Что НЕЛЬЗЯ: большую модель против маленькой (большие недотренировываются
   на 2M и выглядят хуже, чем есть на 11M).
4. Метрики полигона ниже полных (~на 0.02-0.04) — это норм, важны разницы.
5. Победитель абляции переобучается на полных данных перед сабмитом.

Результаты — строкой в таблицу solution/README.md с пометкой "полигон".
