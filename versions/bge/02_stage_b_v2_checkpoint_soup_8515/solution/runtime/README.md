# Stage-B v2 checkpoint-soup USER-BGE-M3 runtime

Исправленная версия runtime-кода для второго кандидата BGE.

Модель основана на `deepvk/USER-bge-m3` и продолжает обучение первого baseline-кандидата. На Stage B использовались ручная разметка, LLM replay и сохранение нескольких промежуточных checkpoint.

Финальная модель получена смешиванием весов:

```text
0.15 × step_00400.pt + 0.85 × step_02000.pt
```

После смешивания был создан один итоговый checkpoint и выполнен экспорт в `model.safetensors`. Во время инференса запускается одна модель — это checkpoint soup, а не ансамбль предсказаний двух моделей.

Public leaderboard score: `0.5520634383301408`.

Эта версия использует:

- инициализацию из Stage A;
- Human Stage B;
- LLM replay из предоставленного `matches_llm.parquet`;
- выбор checkpoint по локальным метрикам;
- смешивание двух checkpoint;
- preprocessing `pair_text_v1`;
- однопроходный инференс одной итоговой модели.

Эта версия не использует:

- symmetry TTA во время инференса;
- одновременный запуск двух моделей;
- усреднение предсказаний нескольких моделей;
- проприетарные LLM или внешние API;
- сетевые запросы во время выполнения solution.

## Отличие от original

Папка `../original` содержит исходный solution в том виде, в котором он был получен от автора модели и отправлен на соревнование.

Папка `runtime` содержит исправленный вариант для воспроизводимого запуска. В нём:

- добавлена поддержка официального аргумента `--output-path`;
- сохранена совместимость с вариантами аргументов через подчёркивание;
- модель загружается только из локальной директории;
- предсказания создаются для всех входных пар;
- пары с отсутствующим или пустым текстом не удаляются;
- сохраняются исходный порядок строк и повторяющиеся пары;
- результат записывается в столбец `predict`;
- preprocessing `pair_text_v1` не изменён;
- подписи runtime соответствуют Stage-B v2 checkpoint soup.

## Подготовка модели

Веса не дублируются в Git. Перед запуском необходимо создать директорию:

```text
models/user-bge-m3-v2-soup
```

и скопировать в неё модель из:

```text
../original/models/user-bge-human-ft
```

Для проверки используется следующий файл:

```text
models/user-bge-m3-v2-soup/model.safetensors
```

Его паспорт:

```text
SHA-256: d51bd8b0170a4a0d307d803050fa8aa1bc525fd2780e8b4faef6a13e8c6e3d93
size_bytes: 1436159092
```

Итоговая структура должна выглядеть так:

```text
runtime/
├── metadata.json
├── README.md
├── run.py
├── models/
│   └── user-bge-m3-v2-soup/
│       ├── config.json
│       ├── model.safetensors
│       ├── sentencepiece.bpe.model
│       ├── special_tokens_map.json

│       └── tokenizer_config.json
└── src/
    ├── __init__.py

```

## Запуск

Находясь в папке `runtime`, выполните:

```bash
python run.py \
  --items_path /path/to/items.parquet \
  --matches_path /path/to/matches.parquet \
  --output-path /path/to/submit.csv
```

Также поддерживаются алиасы аргументов, сохранённые для совместимости с исходным solution.

## Формат результата

Runtime создаёт CSV-файл со столбцами:

```text
id1,id2,predict
```

Каждой входной паре соответствует ровно одна строка результата. Исходный порядок строк и повторяющиеся пары сохраняются.

## Окружение

Runtime рассчитан на официальный образ:

```text
odsai/ecup26-matching-baseline:1.0
```

Модель и токенизатор загружаются только из локальной директории. Доступ в интернет во время инференса не требуется.

## Проверенный контракт

Статическими тестами подтверждено:

- Python-код синтаксически корректен;
- поддерживается аргумент `--output-path`;
- preprocessing совпадает с исходным solution;
- все входные пары сохраняются;
- пустые тексты не приводят к удалению строк;
- ошибочные подписи baseline-кандидата отсутствуют.

Полный запуск с реальными весами и проверка времени выполнения должны проводиться отдельно в целевом контейнере.
