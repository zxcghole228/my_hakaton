# История сборки финального V3 solution

## Что произошло

Первоначальный V3 solution был подготовлен сборщиком:

```text
construction/original/build_submit.py
```

После первоначальной сборки в `src/utils.py` вручную
исправили обработку пар с пустым текстом или отсутствующим
идентификатором товара.

До исправления такие пары пропускались. После исправления
отсутствующий текст заменяется пустой строкой, и каждая входная
пара передаётся модели.

Обучение, веса, tokenizer, preprocessing, symmetry TTA и логика
вычисления предсказаний для обычных непустых пар не изменялись.

## Сохранённый fixed-runtime

Точная версия runtime без весов восстановлена из сохранённой
копии фактически использованного решения и находится в:

```text
construction/fix/runtime/metadata.json
construction/fix/runtime/run.py
construction/fix/runtime/src/utils.py
```

`run.py` совпадает с исходной версией. Единственный изменённый
runtime-файл — `src/utils.py`.

Исправление:

- заменяет отсутствующий текст пустой строкой;
- не удаляет входные пары;
- сохраняет количество строк;
- сохраняет исходный порядок;
- сохраняет дубликаты.

## Сборщик fix

Сборщик:

```text
construction/fix/build_submit.py
```

выполняет следующие проверки:

- SHA-256 каждого runtime-файла;
- SHA-256 config, tokenizer и весов;
- точное содержимое `metadata.json`;
- точный список путей внутри ZIP;
- отсутствие дубликатов и небезопасных путей;
- SHA-256 каждого файла после записи в ZIP.

Архив создаётся плоским: `metadata.json` и `run.py` находятся
непосредственно в его корне. `.DS_Store`, `__MACOSX` и другие
посторонние файлы в него не попадают.

Сборка выполняется через временный файл. Готовый архив заменяет
предыдущий только после полной проверки.

## Побайтовое сравнение ZIP

Полный SHA-256 нового ZIP не обязан совпадать с историческим
архивом. На внешние байты ZIP влияют timestamps, версия zlib,
уровень сжатия, порядок записей и служебные атрибуты.

Контракт воспроизводимости относится к:

- точному набору файлов решения;
- SHA-256 каждого внутреннего файла;
- структуре архива;
- поведению inference-runtime.

Таким образом, сборщик воспроизводит фактический payload
финального V3 solution, не приписывая ему поздние изменения из
`solution/runtime`.
