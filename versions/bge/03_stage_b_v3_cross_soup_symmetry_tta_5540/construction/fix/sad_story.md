# История сборки финального V3 solution

Первоначальный V3 solution был подготовлен с помощью сборщика:

```text
construction/original/build_submit.py
```

Этот сборщик отражает исходный процесс упаковки модели и сохранён в репозитории без содержательных изменений.

После первоначальной сборки в `src/utils.py` было внесено минимальное исправление corner case. Исходный код пропускал пары, если текст хотя бы одного товара отсутствовал или был полностью пустым. В результате для таких пар модель не создавала предсказание, а количество строк в выходном файле теоретически могло оказаться меньше количества входных пар.

Исправление изменило только обработку таких случаев:

- отсутствующий текст заменяется пустой строкой;
- каждая входная пара передаётся модели;
- ни одна строка не удаляется;
- сохраняются исходный порядок и дубликаты.

Веса модели, tokenizer, preprocessing, symmetry TTA и логика вычисления предсказаний для обычных непустых пар не изменялись. Дополнительного обучения, изменения разметки или подбора параметров после этого исправления не выполнялось.

Позднее в репозитории появился улучшенный сборщик:

```text
construction/runtime/build_submit.py
```

Он содержит дополнительные технические улучшения: более строгую локальную загрузку модели, расширенную поддержку аргументов командной строки и дополнительные проверки. Однако этот runtime не является точной копией кода финального solution.

Таким образом, финальный solution представляет собой исходный вариант с одним минимальным исправлением обработки пустых текстов. Он не воспроизводится побайтово ни исходным `original`-сборщиком, ни более поздним `runtime`-сборщиком.

Для фиксации фактически использованного варианта добавлен отдельный сборщик:

```text
construction/fix/build_submit.py
```

Он:

- ожидает точную структуру финальной папки `matching-bge-human-ft-v3-soup-tta-fixed`;
- проверяет SHA-256 runtime-файлов, tokenizer, config и `model.safetensors`;
- создаёт плоский ZIP с `metadata.json` в корне;
- сохраняет модель в `models/user-bge-human-ft`;
- проверяет структуру и целостность созданного архива.

Сборщик `fix` воспроизводит содержимое и поведение финального inference-решения. Общий SHA-256 пересобранного ZIP может отличаться от исторического архива из-за timestamps, порядка ZIP-записей и служебных метаданных упаковки. Это различие не влияет на файлы решения, веса модели или получаемые предсказания.

В репозитории сохранены все три варианта намеренно:

- `original` — первоначальный сборщик и история происхождения решения;
- `runtime` — поздняя технически усиленная реализация;
- `fix` — сборщик, наиболее точно соответствующий фактически выбранному финальному solution.

Такое разделение сохраняет прозрачную историю изменений и не приписывает историческому leaderboard-результату код, который не использовался при подготовке финального решения.
