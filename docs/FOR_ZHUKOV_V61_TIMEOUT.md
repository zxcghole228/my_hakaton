# Дане Жукову: разбор таймаута V6.1 и варианты фикса

## Диагноз по симптому

7 минут жизни = Check (1 мин) пройден, смерть на Public (~115k пар, лимит 6 мин).
GPU-часть каскада влезает с запасом (e5 на 115k + bge на топ-30% с TTA ~ 80-90с
на H100). Значит, 4-5 минут съедает CPU-обвязка. Private (275k / 13 мин) — та же
пропорция, «чуть ужать» не спасёт, нужно убрать балласт структурно.

## Главные подозреваемые (по нашему опыту 6 прошедших пакетов)

1. **pair_signal / построение текстов в одном потоке.** Парсинг JSON-атрибутов
   и сравнение полей на каждую пару питоновским циклом = минуты на 115k.
   Фикс: multiprocessing Pool на все 20 ядер контейнера:
   ```python
   from multiprocessing import Pool
   rows = [(name1[i], attrs1[i], name2[i], attrs2[i]) for i in range(n)]
   with Pool(18) as p:
       signals = p.starmap(build_pair_signal, rows, chunksize=500)
   ```
   Ускорение ~15x. У нас так считаются 96 фичей на 365k за 16 секунд.

2. **Тексты для ВСЕХ товаров файла вместо нужных.** Если items читается целиком
   и тексты строятся по всем строкам — на тесте это лишние минуты и RAM.
   Фикс: потоковое чтение только нужных id:
   ```python
   need = set(matches.id1) | set(matches.id2)
   for batch in pq.ParquetFile(items_path).iter_batches(columns=[...], batch_size=500_000):
       df = batch.to_pandas(); df = df[df["id"].isin(need)]
       ...
   ```

3. **Нет length-bucketing на инференсе.** Сортировка пар по суммарной длине
   текстов перед батчингом = меньше паддинга = x1.3-1.5 к скорости обеих моделей:
   ```python
   order = np.argsort([len(t1[i]) + len(t2[i]) for i in range(n)])
   # инференс по order, preds записывать в исходные позиции
   ```

4. **Мелочи, которые тоже платят**: fp16-веса на диске (быстрее грузятся),
   ленивые импорты torch/transformers (после чтения matches), НИКАКОГО
   torch.compile, TOKENIZERS_PARALLELISM=true.

## Готовый каркас (вариант «взять и не думать»)

Всё перечисленное уже реализовано в наших пакетах, прошедших проверку 5 раз:
`solution/submit_e5base320/src/inference.py` (одна модель) и
`solution/submit_blend2/src/inference.py` (две модели в одном процессе + фолбэк).
Каскад top-30% туда вставляется 15 строками (после скоров e5 отобрать индексы
верхних 30% внутри категории, прогнать bge только по ним, вложить ранги обратно).

Если пришлёшь веса своей E5-stage-B и код своего build_text/pair_signal —
соберу пакет на этом каркасе и прогоню полную эмуляцию на 365k (наш стандарт,
это масштаб Private) сам. Твой build_text перенесу побайтово — это критично,
инференс обязан совпадать с обучением.
