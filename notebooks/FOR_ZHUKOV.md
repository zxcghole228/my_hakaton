# Для Дани Жукова: Пакет 3 — трюки обучения (Kaggle, ~4.5ч)

## Что это и зачем

Мы собираем рецепт финального большого прогона (2 эпохи на 11.2M пар на модели,
которую выберет абляция Бабенко). Твоя часть — проверить в чистом виде два приёма
обучения, которые ты и Мишаня использовали вперемешку с другими изменениями:

| Слот | Что проверяет | Откуда идея |
|------|---------------|-------------|
| tiny_anchor | якорь без трюков | наш боевой рецепт (llm-holdout 0.746 на 11M) |
| tiny_confw | confidence weighting: вес примера 0.75+0.25*abs(2y-1) | Мишаня |
| tiny_catbal | category-balanced: вес категории (median/count)^0.5, клип [0.65,2.0] | ты + Мишаня |
| tiny_confw_catbal | оба вместе — складываются ли эффекты | — |

Каждый слот — 1 эпоха rubert-tiny2 на полигоне 2.17M пар (~1.1ч на T4),
валидация на общем llm-holdout (groupsplit seed 13, уверенные пары, macro PR-AUC).
Порог: трюк идёт в финальный рецепт, если даёт >= +0.003 к якорю.

## Как запустить (важно: НЕ интерактивно, а Commit — про твой интернет см. ниже)

1. kaggle.com -> Create -> New Notebook -> File -> Import Notebook -> вкладка GitHub ->
   репо `zxcghole228/ecup-2026-product-matching`, ветка `egor/llm-solution`,
   файл `notebooks/ablation_tricks_zhukov.ipynb`.
2. Справа Add Input -> датасет с данными соревнования (items.parquet,
   matches_llm.parquet). Туда же должен быть докинут файл полигона
   `data_polygon/llm_sample_2m.parquet` (если его нет в датасете — скачай из репо
   и добавь через New Dataset / версию датасета).
3. В первой код-ячейке поправь путь BASE под имя датасета.
4. Settings (справа): Accelerator = GPU T4 x2, Internet = On.
5. **Save Version -> Save & Run All (Commit)** — и всё.

## Про «отвалится интернет» — не переживай, это главное свойство схемы

**Save & Run All запускает ноутбук в облаке Kaggle на выделенной машине.**
После нажатия кнопки твой интернет, браузер и компьютер больше не нужны:
можешь выключить ноутбук, уехать в тайгу — прогон доедет сам и Kaggle пришлёт
письмо на почту, когда закончится (или упадёт).

Что НЕ надо делать: гонять интерактивную сессию (кнопка Run All в редакторе) —
вот она как раз умирает при обрыве связи.

Дополнительные страховки уже в коде:
- результат пишется в `/kaggle/working/ablation_results.json` после КАЖДОГО слота —
  даже если прогон умрёт на 3-м слоте, первые два сохранены в Output версии;
- при перезапуске (новый Save & Run All) завершённые слоты пропускаются...
  с оговоркой: у НОВОЙ версии свой чистый /kaggle/working, так что реально
  «продолжить» можно, только докинув прошлый json руками — проще дать доехать
  с нуля, слоты дешёвые;
- упавший слот (OOM и т.п.) логируется и пропускается, остальные едут дальше.

## Как следить (опционально)

Страница ноутбука -> вкладка с версией -> Logs. Логи у фоновых версий отстают
на 5-20 минут — это нормально, не паникуй. Мобильный сайт Kaggle логи тоже
показывает. Первая строка `pair/s` появится через ~15 минут после старта
(до этого — подготовка текстов товаров).

Контроль вменяемости: tiny_anchor должен дать full_macro ~0.70-0.72.
Если сильно меньше — пути/данные битые, остальным цифрам не верить, пиши в чат.
