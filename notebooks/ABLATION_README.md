# Для Дани: ночная абляция бэкбонов (notebooks/ablation_overnight.ipynb)

## Зачем это

Выбираем модель для главного прогона на полных 11M пар. Сейчас лучший сабмит
(LB 0.4612) стоит на rubert-tiny2 (29M) — игрушечная модель, потолок близко.
Гипотеза: бэкбон покрупнее даст +0.05-0.1 на локальной метрике (= +0.03-0.06 LB).
Прогон на полных данных стоит 10-30 GPU-часов, поэтому кандидата выбираем
дёшево — на полигоне 2.17M пар (data_polygon/llm_sample_2m.parquet).

## Что сравниваем (матрица в ноутбуке)

| Слот | Модель | Параметры | Зачем |
|---|---|---|---|
| tiny_v1_160 | cointegrated/rubert-tiny2 | 29M | якорь: на 11M дал llm-holdout 0.746 / LB 0.450 |
| sbe_v1_160 | fkrasnov2/SBE | 14.7M | доменная: претрейн на 269M ru e-commerce запросов |
| rubert_base | ai-forever/ruBert-base | 180M | base-класс, русский |
| e5_base | intfloat/multilingual-e5-base | 278M | base-класс, мультиязычный |
| bge_m3 | deepvk/USER-bge-m3 | 568M | тяжеловес, ru-доводка bge-m3 |

Препроцессинг у ВСЕХ один (наш боевой v1) — сравниваем только бэкбон,
"один фактор за раз". Препроцессинг тюним вторым заходом на победителе
(Мишаня параллельно уже гоняет свой v2-текст на e5-small — будет перекрёстная точка).

## Что тебе, скорее всего, придётся поменять

1. **Пути к данным** (первая код-ячейка): BASE, POLYGON_PATH. Нужны:
   items.parquet, matches_llm.parquet, llm_sample_2m.parquet.
2. **Батчи под твою карту.** Выставлены под T4 16GB. На A100/H100:
   tiny/SBE batch 512; base-классы batch 256, accum=1; bge_m3 batch 96-128,
   accum до effective ~256. Больше batch = быстрее.
3. **fp16 -> bf16**: в run_experiment и predict стоит
   `torch.autocast("cuda", torch.float16)` — на A100/H100 замени float16
   на bfloat16 и (важно) `torch.amp.GradScaler(enabled=False)` — с bf16
   скейлер не нужен.
4. **RESULTS_PATH** — файл дописывается после каждого слота; положи туда,
   где переживёт сессию.

## Тайминг (эпоха полигона на слот)

| Карта | tiny/SBE | base-классы | bge_m3 | вся матрица |
|---|---|---|---|---|
| T4 | ~1ч | ~6-9ч | ~20ч (нереально) | не влезает — режь до tiny+SBE+один base |
| A100/H100 | ~15 мин | ~1-1.5ч | ~3-4ч | ~6-8ч, ночь |

Оценки для больших моделей ±50%. Ноутбук печатает pair/s с первых минут —
по первой строке слота пересчитай точно; не успеваешь — убей слот, результаты
предыдущих уже в json.

## Риски и что с ними делать

- **fkrasnov2/SBE**: DeBERTa-v2, проверь max_position_embeddings — если < 160,
  тексты обрежутся сильнее, чем у остальных (это скомпрометирует сравнение —
  тогда пометь в результатах). Лицензия Unlicense — ок.
- **bge_m3 OOM**: 568M на карте < 40GB может не влезть с batch 48 — снижай batch,
  повышай accum. Упавший слот ноутбук пропускает сам (try/except в конвейере).
- **e5 без префиксов query:/passage:**: осознанно игнорируем — при файнтюне CE
  с новой головой эффект мал, а добавлять только e5 = смешать факторы.
- **deepvk/USER-bge-m3 vs BAAI/bge-m3**: взял ru-доводку; если хочешь чистую
  BAAI — замени имя, слот тот же.

## Как читать результаты утром

- Главная колонка `full_macro` (общий llm-holdout seed 13, confident, macro PR-AUC).
  Уровень полигона ниже полных данных на ~0.02-0.04 — важны РАЗНИЦЫ, не абсолюты.
- Якорь tiny_v1_160 должен дать ~0.70-0.72. Если сильно меньше — что-то сломано
  в данных/путях, не верь остальным цифрам.
- Победитель = кандидат на полные 11M (2 эпохи — вторая эпоха проверена, даёт
  прирост: tiny 0.746 -> 0.77 на второй эпохе).
- Если SBE окажется выше tiny при вдвое меньшем размере — сигнал, что домен >
  размера: тогда отдельно обсуждаем поиск доменных моделей покрупнее.
- Результаты — строкой в таблицу solution/README.md с пометкой "полигон" +
  исполненный ноутбук в notebooks/runs/.

## Гипотезы, которые эта ночь закрывает

3. Тянет ли лицензионно-чистый тяжеловес (bge_m3) свои GPU-часы.
