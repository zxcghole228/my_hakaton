# Окружение и зависимости

Эта директория документирует зависимости обучения и инференса трёх BGE-кандидатов.

Оригинальный полный `pip freeze` среды обучения не сохранился. Поэтому репозиторий фиксирует только версии, подтверждённые outputs выполненных notebook, и отдельно отмечает пакеты, точные версии которых не были записаны.

## Reference-файл установки

Подтверждённые основные зависимости собраны в:

```text
requirements/training-cu124.txt
```

Этот файл предназначен для Linux-окружения с Python 3.12, NVIDIA GPU и CUDA 12.4. На macOS его устанавливать не следует.

Пример установки в изолированное окружение на целевой Linux-машине:

```bash
python3.12 -m venv .venv-training
source .venv-training/bin/activate
python -m pip install --upgrade pip
python -m pip install \
  -r requirements/training-cu124.txt
```

Не следует устанавливать эти зависимости в системный Python или использовать параметр `--break-system-packages`.

Файл воспроизводит зафиксированные прямые зависимости, но не является полным lock-файлом всех транзитивных пакетов.

## Зафиксированное training-окружение

Для выполненных экспериментов записано следующее окружение:

| Компонент    | Версия        |
| ------------ | ------------- |
| Python       | `3.12`        |
| PyTorch      | `2.6.0+cu124` |
| Transformers | `4.57.6`      |
| NumPy        | `2.2.6`       |
| pandas       | `2.3.3`       |
| PyArrow      | `23.0.1`      |
| scikit-learn | `1.8.0`       |

Обучение выполнялось на двух NVIDIA H100 PCIe.

Для Stage-B v2 и Stage-B v3 дополнительно зафиксированы:

* distributed backend: `nccl`;
* world size: `2`;
* mixed precision: `bfloat16`.

Version-specific сведения находятся в:

```text
versions/bge/<candidate>/training/environment.json
```

## Импорты training-кода

Проверка всех Python-файлов и code cells notebook подтвердила использование следующих сторонних пакетов:

* `numpy`;
* `pandas`;
* `pyarrow`;
* `torch`;
* `scikit-learn`;
* `transformers`;
* `tqdm`.

Для работы XLM-RoBERTa tokenizer и загрузки весов также могут использоваться зависимости Transformers:

* `tokenizers`;

* `safetensors`.

Точные версии последних пакетов в outputs исходного окружения не были записаны, поэтому репозиторий не присваивает им выдуманные номера версий.

## Runtime-окружение

Все исходные submission используют Docker-образ:

```text
odsai/ecup26-matching-baseline:1.0
```

Точка входа задаётся в `metadata.json`:

```text
python -u run.py
```

Площадка запускает уже подготовленный образ. Файлы установки зависимостей из этого репозитория не заменяют образ и не включаются автоматически в submission ZIP.

Минимальные сторонние импорты runtime:

* `numpy`;
* `pandas`;
* `torch`;
* `tqdm`;
* `transformers`.

Чтение Parquet выполняется через pandas с доступным Parquet engine, которым в training-окружении являлся PyArrow.

## Особенность кандидата 3

В `config.json` экспортированной модели кандидата 3 записано:

```text
transformers_version = 5.6.2
```

При этом в сохранённом training-окружении записано:

```text
transformers = 4.57.6
```

Первое значение является metadata модельного экспорта и не должно автоматически интерпретироваться как версия всего исходного training-запуска.

Это расхождение сохранено в:

```text
versions/bge/03_stage_b_v3_cross_soup_symmetry_tta_5540/training/environment.json
```

и не скрывается заменой одного значения другим.

## Сборщики submission

Исправленные файлы `construction/runtime/build_submit.py` используют только стандартную библиотеку Python:

* `argparse`;
* `hashlib`;
* `pathlib`;
* `shutil`;
* `tempfile`;
* `zipfile`.

Для сборки ZIP не требуется устанавливать ML-библиотеки и загружать что-либо из интернета. Необходимо только иметь локальную модель с ожидаемой контрольной суммой.

## Ограничения

Сохранённые версии основных библиотек позволяют приблизить исходное окружение, но не гарантируют побитовое повторение обучения.

На результат также могут влиять:

* CUDA и драйвер NVIDIA;
* версия cuDNN;
* модель GPU;
* порядок выполнения распределённых операций;
* версии незафиксированных транзитивных зависимостей;
* точная ревизия базовой модели;
* содержимое локальных датасетов.

Эти ограничения необходимо учитывать при оценке воспроизводимости.
