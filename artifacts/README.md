# Артефакты моделей

Эта директория предназначена для локального хранения или временной подготовки больших артефактов, которые не должны добавляться в Git.

К таким артефактам относятся:

* веса моделей `*.safetensors`;
* training-checkpoint `*.pt` и `*.pth`;
* собранные submission ZIP;
* промежуточные экспорты моделей;
* кэши и производные данные.

Основным источником сведений об артефактах являются version-specific manifests:

```text
versions/bge/<candidate>/artifacts/manifest.json
```

## Канонические локальные пути

Для сохранения исходного snapshot финальные веса располагаются локально внутри соответствующей версии:

```text
versions/bge/<candidate>/solution/original/models/<model-directory>/model.safetensors
```

Эти файлы игнорируются Git, даже если физически присутствуют в рабочей копии.

Исправленные runtime и сборщики могут ожидать другое имя модельной директории. Точный путь назначения указан в README выбранного кандидата и в его `version.json`.

Не следует создавать несколько неконтролируемых копий одних и тех же весов. Если копия необходима для сборки, её происхождение должно проверяться по SHA-256.

## Исторические checkpoint

Не все промежуточные training-checkpoint сохранились локально.

Если файл отсутствует, но известны его имя, размер или SHA-256, он документируется в manifest со статусом `not_collected`. Такой статус означает, что файл не включён в репозиторий и не заявляется как доступный.

## Проверка SHA-256

На macOS:

```bash
shasum -a 256 /path/to/artifact
```

На Linux:

```bash
sha256sum /path/to/artifact
```

Полученный hash необходимо сравнивать с manifest выбранного кандидата до запуска runtime или сборки submission.

## Submission ZIP

Полные submission ZIP содержат веса размером более 1 GB и не хранятся в Git.

Исправленные сборщики в `construction/runtime/build_submit.py`:

* используют локальные файлы модели;
* проверяют ожидаемый SHA-256 весов;
* создают inference-only архив;
* не выполняют сетевых запросов;
* не изменяют исторический `solution/original`.

SHA-256 ZIP зависит не только от содержимого модели, но и от структуры архива, metadata, runtime-кода и параметров упаковки. Поэтому hash весов и hash собранного ZIP фиксируются отдельно.

## Правила хранения

В Git не должны попадать:

```text
*.safetensors
*.pt
*.pth
*.bin
*.zip
```

Перед каждым commit необходимо отдельно проверять staged-файлы на наличие весов и архивов.

В репозиторий добавляется только этот README и небольшие текстовые manifests.
