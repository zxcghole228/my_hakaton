# Наше решение: CatBoost на LLM-парах

## Ключевая находка (почему у catboost_v1 было 0.283 на LB)

Тест состоит из **новых товаров**, и его пары по распределению похожи на LLM-пары,
а не на ручную разметку. Модель, обученная только на 365k ручных пар:

- на ручном holdout даёт ~0.62 (локальная метрика Дани честная);
- на LLM-подобных парах — 0.45, причём фэшн-категории почти в нуле
  (Обувь 0.07, Одежда 0.10, Галантерея 0.12, Ювелирка 0.16);
- на LB — 0.283.

**Калибровка**: LB ≈ 0.6 × (наш LLM-holdout). Проверено двумя точками:
- catboost_v1 (Даня): LLM-holdout 0.45 → LB 0.283
- catboost_our_v2:     LLM-holdout 0.608 → LB 0.363

Т.е. локальная LLM-валидация предсказывает LB — можно итерироваться без сабмитов.

## Валидация (одинаковая во всех экспериментах — не менять!)

Групповые сплиты union-find по товарам (товар не может попасть и в train, и в val):

- manual holdout: seed 42, 20% компонент (`train.py: group_split`)
- llm holdout: seed 13, 3% компонент, метрика на уверенных парах
  (target<=0.2 | >=0.8, бинаризация по 0.5)

Метрика: macro PR-AUC по 20 категориям (`average_precision_score`).

## Результаты

| Модель | manual holdout | llm holdout (macro) | LB |
|---|---|---|---|
| catboost_v1 (только ручные) | ~0.62 | 0.453 | 0.283 |
| our_v2 (2.8M LLM + ручные) | 0.625 | 0.608 | 0.363 |
| our_v3 (все 11.2M LLM) | 0.615 | 0.645 | 0.374 |
| ce-v1 A+B (rubert-tiny2) | 0.721 | 0.685 | 0.4355 |
| ce-v1 stage-A only | 0.632 | 0.746 | 0.4500 |
| stack v1 (GBM + ce_score) | 0.686 | 0.762 | 0.4612 |
| ce tiny-2ep stage-A | 0.649 | 0.771 | **0.4623** |
| catboost Дани v2 (10k шагов + TTA) | — | — | 0.4432 |
| e5-small Мишани (30k шагов) | — | 0.786 | **0.4839** |
| stack v3 (96 фичей + CE-2ep) | 0.703 | 0.784 | 0.4733 |

Калибровка LB ≈ k × llm-holdout, k сползает с ростом модели: 0.625 → 0.597 → 0.580.
Для прогнозов берем ~0.57-0.58.

Вывод по GBM: x4 данных дали +0.011 на LB — фичевый бустинг выходит на плато.
Главная ветка — cross-encoder: уже на tiny-модели llm-holdout 0.685-0.74 (vs 0.645 у GBM).
Стадия B (manual-дообучение) сильно качает manual-метрику (0.63→0.72), но роняет
llm-метрику (0.746→0.685). Что лучше для LB — проверяется парным сабмитом.

## Файлы

  == `8500892sx` + цифровые ядра), кросс-матч кодов имя↔атрибуты, конфликты

- `train.py` — v1: только ручные пары (baseline сравнения, 0.630).
- `train_v2.py` — v2: 2.8M LLM-пар soft labels (CrossEntropy) + ручные с весом 5.
- `prep_v3.py` + `train_v3.py` — v3: фичи по всем 11.2M LLM-пар чанками, обучение.
- `submit/` — готовый пакет сабмита (модель v2 внутри). Для полного архива нужно
  довендорить бинарные зависимости (не в гите): `vendor/catboost` (линуксовый,
  cp312, есть в архиве catboost-сабмита) и `vendor/rapidfuzz` (3.13.0,
  `pip download rapidfuzz --platform manylinux2014_x86_64 --python-version 312
  --only-binary=:all:`, распаковать wheel). Затем `zip -r submit.zip .` изнутри
  папки. Тайминг: 365k пар за 6.5 сек на M5 Pro (лимит 13 мин — запас ~100x).
- `../notebooks/ozon_ecup_crossencoder_v1.ipynb` — для Kaggle GPU: файнтюн
  rubert-tiny2 на LLM-парах, сплиты и метрика те же. Ожидаемый следующий скачок,
  особенно в фэшн-категориях.

## Трюки обучения (абляция Жукова + вывод о взаимодействии)

catbal соло -0.025 (вред), confw соло -0.005 (шум), ВМЕСТЕ +0.004 (норм).
Неаддитивность x4 выше шума => взаимодействие реально: catbal раздувает редкие
категории с самой грязной разметкой, confw эту грязь глушит. Правило: эти два
трюка — только парой либо никак. Шум полигона (один сид) ~= +-0.008 —
эффекты меньше 0.01 требуют 2-3 сидов.

Текущий большой прогон e5-base@320 запущен с confw-соло (знание пришло позже
запуска) — ожидаемый эффект в пределах шума, не перезапускали.

## Public/Private: правила финала (30/70, 115k/275k пар)

1. Шум public-метрики ~= +-0.003-0.005 (115k пар, 20 категорий). Разницы
   меньше ~0.005 на public неотличимы от шума — не сабмитим ради них и не
   делаем из них выводов.
2. Не переобучаемся под public: решения принимаются по локальному holdout,
   LB только якорит калибровку. Топ public != финальный порядок: отрыв
   ~0.005-0.01 может перевернуться на private.
3. Два финальных решения выбираем ПО ЛОКАЛЬНОЙ валидации, не по public:
   агрессивное (лучший ансамбль) + консервативное (лучшая одиночная модель
   без рискованных надстроек).
4. Public+private = 390k пар, сплит случайный по одному пулу — public
   репрезентативен, калибровка x0.60 должна перенестись на private.
5. Тайминги: public 6 мин на ~115k, private 13 мин на ~275k — при ансамблях
   large-моделей проверять оба бюджета.
